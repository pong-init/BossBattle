System Design

Architecture.

A 4-node LangGraph pipeline where each node receives only the tools it needs. Triage uses pure LLM reasoning with no tools. Context gathering gets GitHub. Ticket creation gets Linear. Notifications get Slack + Gmail.

Build Experience

What Worked & What Didn't.

✓ What Worked

Arcade Headers Auth

The original plan anticipated complex OAuth interrupt handling. Arcade Headers (API key + user ID) meant the agent just worked. No interactive auth, no token expiration, no 3am problems.

MCP Gateway as Single Endpoint

One URL, one client, all tools. The Gateway's design aligned perfectly with langchain-mcp-adapters. Eliminated ~100 lines of per-server configuration.

Model Agnosticism

Swapped OpenAI → Gemini at the LangChain level with minimal friction. The Gateway genuinely doesn't care what LLM you use.

Tool Routing Architecture

Per-node tool binding worked elegantly. Triage gets zero tools (pure reasoning), each subsequent node gets exactly what it needs.

✗ What Didn't

GitHub 404 Bug

github.com/owner/repo/repos/owner/repo/pulls
URL path doubled, hitting github.com instead of api.github.com. Platform bug in Arcade's GitHub tool — raw 404 with no context caused misdiagnosis.

Eval Framework Lock-in

arcade_evals hardcoded OpenAI assumptions: seed=42, strict:true. Broke immediately with Gemini. Required contributing PR #783 to fix.

Observability Took 3x Longer

Plan said "~1 hour." Reality: 3 hours. Traces ≠ metrics, rate() on batch data = NaN, Docker networking breakage when adding Tempo.

Error Messages Are Opaque

Raw HTTP 404s with no context. No suggestion of what went wrong or how to fix it. Both human and LLM misdiagnosed the same error.

"Architecture plans survive. Integration details don't. The 4-node pipeline was exactly right. Every library choice and auth assumption changed on contact with the tools."

Platform Analysis

Gap Analysis.

Every gap below was discovered hands-on, not theorized. They're ordered by how much they'd block an enterprise customer from going to production.

Critical

No Native Observability

Every tool call flows through the Gateway — Arcade sits on the most valuable telemetry data in the agent stack. But there's no OTLP export, no span correlation, no cost tracking. Developers must build the entire OTel pipeline from scratch.

Critical

Error Messages Are Not Actionable

The GitHub 404 bug produced a raw HTTP error with no context. Both human and LLM misdiagnosed it. Enterprise tools need errors that say what went wrong, why, and what to try next.

High

Two-Tier Tool Problem

Custom tools registered via the SDK don't get the same auth flow, OTel spans, eval harness, or discovery as native tools. Two classes of tools — observable natives and invisible customs — is worse than no gateway at all.

High

Eval Framework Assumes OpenAI

A model-agnostic platform needs model-agnostic evaluation. arcade_evals hardcodes seed=42, strict:true, and string tool names — all OpenAI-specific. PR #783 fixes this.

Medium

Gateway ≠ Framework Positioning

Arcade's moat is auth aggregation, tool composition, and the write path. Pushing the MCP Server SDK as "build your own" dilutes this positioning. The Gateway is the product; the SDK is a commodity.

Medium

Onboarding Friction

The Gateway Assistant MCP exists but isn't surfaced. Dropping into the dashboard is clunky. The first-run experience doesn't show developers the "aha moment" fast enough.

Strategy

90-Day Roadmap.

Three months, three themes. Each month builds on the last. The sequence matters: you can't sell governance to the C-suite until the developer experience is solid.

Month 1 — Growth & Usability

Lean into what's already there

The Gateway Assistant MCP exists but I didn't know about it until deep into the build. The dashboard is clunky. The first-run experience matters more than any feature.

Developer onboarding Gateway discovery Error messages Dashboard UX

What we're NOT doing: New integrations. Fix the experience with existing tools before adding more.

Month 2 — Gateway as Platform

Ship what Anthropic isn't building

Anthropic is pushing MCP registries and remote servers. They're building the transport layer. Arcade's moat is auth aggregation, tool composition, and the write path. Double down on the Gateway — that's the product.

Native OTel export Custom tool parity Provider-agnostic evals Cost tracking

What we're NOT doing: Building our own MCP server SDK. That's commodity infrastructure. Focus on what flows through the Gateway.

Month 3 — Enterprise Governance

Ship Tron — take the C-suite conversation

Security teams can't wrangle agentic AI today. Config-driven policy enforcement — declarative YAML that non-coders can audit and edit — is how you move from "developer tool" to "enterprise platform." It's also how you expand the buyer from engineering to security and compliance.

Policy engine Contextual Access Audit logging Compliance controls

What we're NOT doing: Full IAM. Start with tool-call governance. Prove the pattern works before expanding scope.

Vision

Beyond 90 Days.

The 90-day roadmap is tight and self-contained. These are the next horizons — informed by the build but requiring more market signal before committing resources.

♦ Agent Gateway (not just Tool Gateway)

Today, Arcade sees every tool call. With an LLM proxy layer, it sees every prompt too. Combined: every prompt and every action in one audit log. This is the "full-stack agent observability" play.

"LiteLLM does exactly what Arcade doesn't: it sits between the agent and the LLM. Combined, you'd own both traffic streams."

♦ Open Source Partnership Strategy

The smart move: prove demand first with an open-source integration (LiteLLM, OpenLLMetry) before committing engineering resources or M&A capital. Co-partnerships validate the thesis cheaply.

LiteLLM OpenLLMetry Prove demand first

Let's Talk

Collaboration Questions.

A take-home should start a conversation, not end one. These are the questions I'd want to discuss with the team.

01

Governance Buyer

Who buys Contextual Access today? Is the buyer engineering (DevOps/platform teams) or security/compliance? Does the roadmap sequence change if governance is already the wedge?

02

Gateway vs. SDK Strategy

How does the team think about the Gateway (consumption) vs. MCP Server SDK (creation) positioning? Is there a world where both win, or are they inherently in tension?

03

Observability Ownership

The Gateway sees every tool call. How far should Arcade go into the observability space? Native OTLP export? Full dashboard? Or partner with existing tools (Datadog, Grafana Cloud)?

04

Enterprise Readiness

What's the biggest gap between current state and enterprise-ready? Is it governance? Observability? Multi-tenancy? SOC 2? The answer changes the roadmap sequence.
